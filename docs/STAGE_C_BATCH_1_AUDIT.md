## Test-first changes in this batch

1. Added reminder privacy/UI tests first; the initial six failed against the old group-visible list and help-routing button. Implemented private-only listing and an actor-scoped Clear all callback; then added replay, input-boundary and DB-failure coverage. `/remind`, `/reminders`, and `/forget` now report persistence uncertainty with safe recovery guidance. Fourteen reminder-focused tests pass, including a simultaneous near-limit admission regression; cross-instance caps remain unverified.
2. Added concurrent AFK handler tests first; both failed because the old code used a non-atomic `find_one` then `update_one`. Replaced it with a cooldown-conditional atomic Mongo update; 2 tests pass.
3. Added `/afklist` pagination tests first; they reproduced ignored page arguments, unbounded output and uncaught database errors. Added 10-row paging, bounded/clamped page input, count disclosure, explicit bot-wide scope, read-only callback group/message checks and actionable storage errors; 5 tests and 4 input subtests pass.
4. Added `/whois` tests first; a generic Telegram exception was displayed as “not a member.” Only the explicit `UserNotParticipant` error now maps to non-membership; other API failures are reported as unverified. Four tests pass.
5. Added missing-actor `/inbox` test first; it reproduced an `AttributeError`. Added a fail-closed identity check; 1 test passes.

Additional discovery correction: six private-only handlers (`/feedback`, `/inbox`, `/mydata`, `/preferences`, `/reminders`, `/sudohelp`) are now labeled `private` in the bot registry guide and webapp instead of the misleading `Any chat`; handlers still enforce their own boundaries.

Combined focused validation (source/test-only, mocked/offline): **179 passed, 732 subtests passed** across command registry, command UI/presentation/navigation, accessible help, bot API/experience, stats, member data/preferences, Telegram helpers and Batch 1 regression files. Webapp checks: 223 tests and `npm run typecheck` passed. Live Telegram, MongoDB, staging and device validation were not performed.

## Residual limitations and remaining Stage C work

- The pending-reminder cap is serialized per sender within one bot process. A multi-instance deployment could still exceed 20 because no shared reservation/transaction exists. The current Render manifest declares one service but does not make single-process operation a database invariant; do not claim a cross-instance cap.
- Reminder delivery stays at-most-once when Telegram or Mongo outcomes are ambiguous. A process crash after a `pending` → `sending` claim can leave a stale `sending` row; recovery must not blindly resend and risk duplicate Telegram messages. Design durable claim/reconciliation before changing this behavior.
- The focused Python suites and webapp tests/typecheck passed, but the repository-wide Python suite remains incomplete (a previous broad run aborted near 95%). Keep that status separate; do not claim the full suite passed.
- No live Telegram, MongoDB, staging, browser or device verification was performed.
- Batch 1 covered only the 27 live `tools` commands. The other 182 live commands, six historical removals, broader callback surfaces and final cross-command dead-code/performance/regression review remain for Batches 2–7 and final audit. The overall Stage C task is **not complete**.
