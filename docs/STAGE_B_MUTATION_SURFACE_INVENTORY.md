# Stage B mutation-surface inventory

**Audit date:** 2026-11-01
**Scope:** source-backed inventory of Telegram commands/callback actions, web API route files, internal Flask route declarations, and Python functions containing direct Mongo-style write calls.
**Status:** broad inventory and sampled control-flow review; **not a proof that every mutation is correctly authorized**. The CSVs are navigation aids generated from source syntax. Review the implementation and tests before treating any source cue as an authorization guarantee.

## Evidence reviewed in this continuation

- Confirmed `_internal_authorized()` requires a non-empty configured `WEBAPP_SECRET` and compares the supplied `X-Videl-Internal` value with `hmac.compare_digest`.
- Re-read owner/player auth helpers and the Next route inventory test. The latter checks that each API route declares an expected role guard or explicit auth boundary; it does not verify that the guard dominates each write or enumerate all side effects.
- Reviewed callback registrations and keyboard action expressions from source, including owner/sudo panel, connected settings/filter editors, preferences, FAQ, captcha, approval/blocklist, music controls, and Group Manager paths. Sensitive sampled paths recheck roles/target bindings; read-only/help/personal paths are not equivalent to admin mutations. This sampling did not verify every indirect helper call.
- Reviewed sudo registration and execution: `/addsudo`, `/delsudo`, `/rmsudo`, and `/sudolist` use the owner policy; the owner-only removal callback rechecks private owner and bot-panel identity. Sudo does not satisfy connected group-admin authorization. `/voicequality` and `/voicehealth` require owner or active sudo in the owner's private chat; `/restart` is private-owner-only.
- No new source-backed authorization vulnerability was confirmed in this continuation, so no Stage B source fix or new regression test was warranted. This is **not** a statement that the full inventory has zero gaps.

## Explicit remaining evidence gaps

1. The generated static inventories do not replace manual trace of every command/callback from actor and target inputs through each helper and side effect. In particular, each of the 209 live commands and every one of the 157 write-containing functions still needs explicit test/evidence mapping before claiming exhaustive path-by-path proof.
2. Some older immediate group commands are compatible-by-design and lack preview/confirmation; confirm that this is intentional for each destructive verb. Matrix entries describe the approved-list and blacklist clear cases that already have explicit confirmation.
3. Stateless owner/player cookies have no immediate per-token revocation ledger. Group Manager rechecks current Telegram admin status, but owner-cookie logout alone cannot invalidate a copied bearer token before expiry or secret rotation.
4. Storage, bot rights, concurrency and ambiguous-delivery tests are mocks/offline only. Production MongoDB transaction/acknowledgement behavior, live Telegram rights/revocation, cross-process worker races, staging, browser, and device/WebView behavior were not validated.
5. `#234` remains blocked on owner/maintainer credential revocation, production-copy verification, and coordinated history remediation. `#248` remains open pending staging, recovery, and release validation.
